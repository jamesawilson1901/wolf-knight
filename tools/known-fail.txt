# A nightly sweep that is permanently red teaches everyone to ignore it —
# that is how two regions played the wrong music for weeks (docs/TESTING.md
# §1). A failure that has been PROVEN pre-existing (§6's git-worktree rule:
# check out live main in a worktree, run the suite there, watch it fail the
# same way) goes here instead of turning the sweep red for something no
# change in flight caused.
#
# Format, one entry per line, pipe-separated:
#   suite.mjs | reason | YYYY-MM-DD proven
#
# verify-all.sh reads this: a listed failure reports as an expected
# KNOWN-FAIL (green), not a red FAIL, and is never retried (retrying a
# documented, expected failure just burns CI minutes every night). A listed
# suite that unexpectedly PASSES reports as a "stale known-fail" warning —
# visible, but not red — so this list cannot quietly rot into a lie either.
#
# Removing an entry: once the underlying room/system is actually fixed, the
# suite will show as a stale known-fail on its own; delete the line then,
# don't wait for someone to notice the warning.
